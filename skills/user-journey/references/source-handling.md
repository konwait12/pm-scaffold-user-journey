# 来源处理（Source Handling）

## 来源登记（Source Register）

为每个来源分配一个稳定 ID 并记录：

```text
source_id
title_or_description
format
author_or_speaker
provided_by
created_at
retrieved_at
authority_scope
location_or_link
notes
```

使用 `SRC-001`、`SRC-002` 等。对于会议，区分会议纪要原文与 AI 生成的摘要。

如果本次工作指定了项目专属基线（例如飞书/钉钉/Notion 上的项目章程文档、决策记录或既有 PRD），通过对应 CLI 读取时，必须保留原文位置；基线原文、摘要/纪要和 AI 解读分开登记，不能把摘要当作原始证据。基线原文由 PM 在本轮明确指定并写入治理伴随文件的"项目专属基线读取记录（可选）"段。

## 提取规则（Extraction Rules）

1. 在规范化之前先提取来源陈述。
2. 对实质性主张保留说话人或作者与位置。
3. 区分显式陈述与隐含含义。
4. 当被排除的内容看似承载需求但属于范围外或重复时，记录一条简短原因。
5. 绝不把"没有提及"当作需求不存在的证据。

## 权威性（Authority）与冲突

不要定义通用的来源类型优先级。用以下方式评估权威性：

1. 针对本项目是否有显式的人工确认；
2. 对特定业务事实或目标的决策权；
3. 来源的直接程度；
4. 时效性，以及后续陈述是否显式取代先前陈述；
5. 独立来源的相互佐证。

当陈述冲突时：

- 保留双方的陈述与来源 ID；
- 说明每种解读的影响；
- 识别可能的事实负责人或决策负责人；
- 当冲突改变实质性结论时，标记为 `conflict` 并停下；
- 绝不要悄悄选择更"方便"的陈述。

## 调研边界（Research Boundary）

如果本次工作指定了项目专属基线（例如飞书/钉钉/Notion 上的项目章程文档），除了 PM 明确授权读取的基线原文之外，不要用联网搜索或外部案例填补旅程事实，除非 PM 在本轮明确授权并指定用途。任何获授权的外部资料都只能作为方法或待核实线索，不能确认内部角色、范围、目标或路径。调研不能确认内部业务意图、项目范围、业务归属或风险的可接受性，把这些提交给负责任的人类。

## 混合媒体（Mixed Media）

- 对于幻灯片与文档，保留幻灯片/页面/章节位置。
- 对于图片，转录可见的承载需求文本并注明不确定性。
- 对于会议记录，区分说话人陈述、决策、建议与未决讨论。
- 对于邮件线程，保留发件人、收件人上下文、日期，以及后续邮件是否取代先前邮件。
